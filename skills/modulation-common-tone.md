# Common-Tone Modulation

## Purpose

Plan a key change that preserves audible continuity.

## Use when

- plan a modulation using common tones

## Do not use when

- when the music must remain in one unambiguous key

## Inputs

- chord tones or a harmonic progression
- key, meter, and phrase context

## Outputs

- Roman-numeral or function analysis
- candidate chord and cadence choices

## Procedure

1. Name source and destination keys.
2. Find pivot or common-tone material.
3. Verify the cadence that confirms the destination.

## Hard constraints

- Do not call a brief tonicization a modulation without evidence.
- Keep spelling valid in both keys.

## Heuristics

- Prefer a pivot supported by bass and phrase function.
- Use common tones as anchors during the transition.

## Validation status

P1 has no implemented engine validator for this card. Treat every result as advisory until P2 provides named operations and validators; do not describe an unimplemented check as performed.

## Failure modes

- Changing key labels without a confirming cadence.
- Selecting a pivot that requires awkward spelling.

## Examples

- A pivot chord between relative keys.
- A common-tone bass transition into a new cadence.
